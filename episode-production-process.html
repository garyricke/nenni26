How an episode gets made

The repeatable process behind every Building Efficiency Podcast episode — from Jim's handoff in Riverside, through the Descript cleanup and the Squarespace install, to the deep-dive landing page and its assets. This is the version of record. If a step here is wrong or has drifted, fix this page first, then the episode.

01

What Jim hands off

Every episode starts with a note from Jim. Four things need to be in it. If any are missing, ask before starting — each one is load-bearing later, and reconstructing them after the fact is what causes rework.

The four inputs

  • The guest's LinkedIn URL. Used for the bio modal, the show notes, and to confirm name spelling, job title, and credentials. Descript transcribes phonetically — the transcript is not the source of truth for how a name is spelled.
  • The Riverside project link, pointing at the ?activeTab=exports view. Not the recording page — the exports tab, because that is where the export variants live.
  • The breakout video(s), called out by name. Riverside auto-titles these, and the auto-title often has nothing to do with the episode title.
  • The episode title. Jim's title is canonical. See Title vs. hook — this is the single most misunderstood part of the process.
Ambiguity to resolve up front

When Jim writes “the exports section has one breakout video” and then a Title: line, it is genuinely unclear whether the title names the video or the episode. Resolve it before building. On Ep 146 the downloaded clip was Abby's CMTA overview (2:47–3:33), while the supplied title was “The Hidden Value of Data and Authentic Conversations in Winning Healthcare Projects” — material that actually sits around 8:00–10:00. Those cannot both describe the same 46 seconds.

02

The episode folder

Everything for one episode lives in one folder, named {Guest-Name}-{DDmonthYYYY}, under nenni26/episodes/. Nothing related to the episode lives anywhere else. Only the finished landing page graduates to the project root.

episodes/Abby-Lauck-10june2026/ ├── Abby-Lauck-Riverside-Descript.mp3 # final audio (the file uploaded to Squarespace) ├── Abby-Lauck-Riverside-Descript.md # Descript transcript, 5-second timestamps ├── profile-abby-lauck-1.jpeg # headshot(s) pulled from LinkedIn ├── profile-abby-lauck-2.jpeg ├── riverside_…_studio.mp4 # breakout video export ├── riverside_magic_episode….wav # unused source variant, kept for reference ├── bep-ep146-thumb.png # 9:16 thumbnail master, 1536x2752 ├── bep-ep146-thumb.jpg # optimized, 1080x1920, ~150 KB -> Squarespace └── ep146-show-notes.md # RSS tiers, timestamps, fact-check notes nenni26/ └── ep146-lauck.html # the landing page (root, not the episode folder)
Changed as of Ep 146

The generated thumbnail now lives in the episode folder, not in generated_imgs/, so an episode is self-contained and can be handed to someone else as a single directory. Both a PNG master and an optimized JPEG are produced.

03

Audio: Riverside → Descript

Riverside offers several exports of the same conversation — raw, studio sound, and a “magic episode” cut with filler removed. They differ in length and in processing, and picking the wrong one has cost us a full re-edit before. Confirm with Jim which export you are pulling, then never switch mid-episode.

Jim's own export usually has studio sound, removed fluff, and removed filler words applied. We do not use it directly: Descript's filler-word removal is better. We take the cleaner source and do our own pass.

The Descript pass, in order

  1. Import the Riverside audio into Descript. Name the project with the guest's name.
  2. Studio Sound: off. It has been the source of artifacts — a lisp on one guest, an echo on another. Leave it off unless Jim specifically asks.
  3. Remove all filler words. Leave any harsh cuts it creates untouched at this stage.
  4. Remove word gaps greater than 0.75 seconds, and edit those regions.
  5. Spot-check the intro. Listen to the opening and hand-fix anything the automatic passes made choppy.
  6. Spot-check the outro. Same treatment — the goodbye should not sound clipped.
  7. Set speakers to 2 and label them explicitly: Jim and the guest's name. This is what makes the transcript usable downstream.
  8. Export the audio into the episode folder as {Guest-Name}-Riverside-Descript.mp3.
Why the filename says “Riverside-Descript”

The suffix encodes the provenance: a Riverside export that then went through a Descript cleanup. Six months from now, when there are three MP3s of similar length in a folder, that filename is the only thing that tells you which pipeline produced which file.

04

Transcript export

Export the transcript from Descript as Markdown, with timestamps set to appear every five seconds, and save it beside the audio using the same base name.

Five-second granularity is the whole point. It is what allows chapter markers, show-note timestamps, and video-clip captions to be anchored precisely rather than guessed. A transcript with per-paragraph timestamps is not good enough.

The transcript must match the audio you ship

Every chapter timestamp on the landing page is derived from this transcript. If you later re-edit the audio, the transcript is stale and every timestamp is wrong. Re-export it. A quick sanity check: the transcript's last timecode should land within a few seconds of the MP3's duration.

05

The Squarespace install

Duplicate the previous episode's podcast entry rather than building a new one — it carries the block structure and settings forward. Then swap in this episode's content.

What to set

  • Upload the exported MP3 into the audio block.
  • Use Jim's title, verbatim, as the episode title.
  • Put the episode number in the title of both the audio block and the podcast entry, so the two never drift apart.
  • Set the season — currently Season 6 — and increment the episode number by one.
  • Enable the download button.
  • Paste the short description and summary from the generated show-notes Markdown into their matching fields.
The audio URL changes every time you re-upload

Squarespace mints a brand-new CDN URL each time a file is uploaded to the audio block, and the old URL keeps serving the old MP3 indefinitely. The landing page hard-codes that URL, so replacing the audio does not update the page. If you swap the audio, send the new URL over and the page's <audio src>, duration labels, and chapter timestamps all need revisiting.

06

The Claude Code build

With the folder populated and the audio live on Squarespace, hand over two things: the Squarespace MP3 URL and the episode folder path. Everything else is derived.

What gets produced

  • The landing page, epNNN-{lastname}.html — a Squarespace code-block embed with a custom audio player, chapter list, timeline, market tabs, pull quotes, accordions, the Signature Four, and concept primers.
  • The show notes, epNNN-show-notes.md — subtitle, summary, and full description drafted at three lengths because podcast apps consume different fields, plus timestamped chapter bullets and internal fact-check notes.
  • The 9:16 thumbnail, PNG master plus optimized JPEG, both in the episode folder, plus a Cloudinary upload.
  • Cloudinary uploads for the headshot and the video clip.
Checks that run automatically

The hosted MP3 is byte-compared against the local export to prove the transcript matches the audio. The breakout video is located inside the episode by audio cross-correlation, so its caption and timestamp are exact rather than assumed. Every factual claim the guest makes on air — rankings, program names, project figures — is checked against primary sources, and discrepancies are surfaced rather than silently corrected.

07

Assets & naming

All images and video are hosted on Cloudinary (cloud dsbllwpbh) and delivered with f_auto,q_auto so browsers get WebP or AVIF automatically. Nothing raster is committed to a repo.

Public IDs

  • bep-ep{NNN}-{slug}-profile — guest headshot, delivered w_240,h_240,c_fill,g_face
  • bep-ep{NNN}-clip{N} — breakout video, uploaded as video/upload
  • bep-ep{NNN}-thumb — the 9:16 social thumbnail
Video posters cost nothing

Once a clip is on Cloudinary, its poster frame is derived from the video itself — no second upload. Insert so_24.0,f_jpg,q_auto,w_1200 after /upload/ and change the extension to .jpg, where so_ is the seek offset in seconds. Pick a frame where the speaker's eyes are open.

Two thumbnail files, two jobs

The PNG master (1536×2752) is the archive copy and the source for any future re-crop. The optimized JPEG (1080×1920, under 300 KB) is the one that gets uploaded to Squarespace. Keeping both in the episode folder means nobody has to regenerate artwork to make a small change.

08

Title vs. hook

These are two different pieces of text doing two different jobs, and they are not interchangeable. Confusing them is the easiest way to make the podcast look inconsistent across platforms.

The Title

The Hidden Value of Data and Authentic Conversations in Winning Healthcare Projects

Jim writes it. It is canonical and gets used verbatim.

Where it appears: the Squarespace audio block, the podcast entry, the RSS feed, and the title bar of the landing page's audio player.

What it optimizes for: being found. It is the string a listener sees in Apple Podcasts or Spotify, so it should be descriptive and carry the subject matter. Length is fine.

The Hook

She was the client first.

We write it, drawn from the conversation, and Jim approves it.

Where it appears: the hero headline of the deep-dive landing page, and the headline band of the 9:16 social thumbnail. Nowhere else.

What it optimizes for: stopping a scroll. Three to five words, concrete, a little bit of a curiosity gap. It never has to explain the episode — the page does that.

The rule

When Jim supplies a title, it wins every field called “title.” The hook lives only in the hero and on the thumbnail, and never replaces it.

When Jim has not supplied a title yet — which happens, because the landing page is often built before the episode is scheduled — the hook is promoted to a working title so the page is not blank. It is provisional. The moment the real title arrives, it is swapped in, and the hook retreats to the hero.

09

Pre-publish checklist

  • The MP3 on Squarespace is the same file as the local export — compare byte size, not just duration.
  • The transcript's final timecode lands within a few seconds of the MP3 duration.
  • Guest's name spelling confirmed against LinkedIn, not the transcript.
  • Episode number matches across the audio block, the podcast entry, the page, and every Cloudinary public ID.
  • The page contains zero non-ASCII bytes, comments included.
  • The extracted <script> block passes node --check.
  • Every chapter timestamp is monotonic and none exceeds the audio duration.
  • The play button is clickable while the spinner is showing.
  • Every tab, accordion, reveal card, and modal opens and closes; Escape closes modals.
  • Every Cloudinary URL and the audio URL return a 200 or 206.
  • The change log has an entry for this episode.
10

Known pitfalls

Each of these cost us real time at least once. They are listed so they cost us that time only once.

Template from the newest page, never an older one

  • Ep 146 was built from the Ep 144 template and silently inherited two bugs that had already been fixed in Ep 145: a play-button deadlock (pointer-events: none while loading, so the click that would start loading could never land) and upside-down ±15s skip icons. Both had to be re-fixed. Always start from the most recent episode page.

One non-ASCII character kills the entire script

  • A single em dash in a JavaScript comment once threw Uncaught SyntaxError in the Squarespace-rendered page and killed all the player JavaScript — presenting as an unrelated “audio won't load” bug. Escape non-ASCII per context: HTML entities in markup, \uXXXX in JavaScript, \HHHH in CSS. Never blanket-replace.

Riverside export drift

  • On Ep 145, the “magic episode” export was 55 minutes but the source pulled for editing was 58 minutes and carried an echo. The echo lived in the Riverside source, not in anything Descript did. Confirm the exact export with Jim before touching the audio.
  • A Descript “magic edit” trims non-uniformly. You cannot subtract a constant from the chapter timestamps — on Ep 145 one chapter moved later even though the episode got shorter. Re-anchor every chapter individually from the new transcript.

Guests misremember, and transcripts spell phonetically

  • Verify rankings, program names, and project figures against primary sources. On Ep 146, “ranked number two nationally” in K-12 was true in 2023 and 2024 but is #3 in the 2025 BD+C Giants 400, and the “Public Military Installation Fund” is formally the Public Schools on Military Installations (PSMI) program.
  • Do not silently repeat a stale claim, and do not silently correct a guest either. Pick a framing that stays true, then flag the discrepancy so Jim owns the call.
  • Transcripts render names by ear: “Louk” for Lauck, “Forestall” for Forrestal, “Gale” for Goehl. Confirm every proper noun.
